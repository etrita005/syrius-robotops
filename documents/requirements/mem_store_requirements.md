# MemStore 模块最终技术需求清单

## 一、核心基础能力需求

- 提供前端可直接调用的 KV 读写能力，支持对象型数据存取、删除，底层基于内存 LRU 策略做容量淘汰

- 支持单 Key 独立生命周期配置，每条缓存数据可自定义不同 TTL 过期时长，超时自动失效清理

- 缓存数据全部内存托管，无需部署 Redis、无需部署消息队列，轻量化无中间件依赖

## 二、自动刷新触发能力需求（全部对接自研任务引擎，不自行执行业务数据计算）

- 支持单 Key 自定义预到期通知能力：每条 Key 可配置独立提前预警时长，缓存即将过期时，通过任务流引擎执行前端添加key时提供的获取数据任务流DAG，完成数据刷新更新

- 支持缓存未命中触发刷新：前端查询 Key 缓存不存在/已失效时，通过任务流引擎执行前端添加key时提供的获取数据任务流DAG，完成数据刷新更新

- 支持单 Key 自定义周期定时刷新：每条 Key 可独立配置 Cron 定时规则，按固定周期通过任务流引擎执行前端添加key时提供的获取数据任务流DAG，完成数据刷新更新

- 所有数据获取、数据更新动作，均依赖前端添加Key时传入的获取数据任务流DAG，全权交由自研任务流引擎执行，本模块仅负责触发调度、缓存管理、前端推送，不执行业务数据计算与子任务编排

## 三、前端实时推送能力需求

- 基于 Hono 原生 SSE 实现长连接订阅，支持前端按 Key 维度订阅数据更新

- 后端任务引擎完成数据更新、回调模块刷新缓存后，自动通过 SSE 实时推送最新数据至对应订阅前端

## 四、动态资源管理需求

- 前端新增缓存Key时，除基础配置外，需指定任务流引擎所需的获取数据任务流DAG（JSON格式），作为该Key所有刷新场景的统一数据来源执行依据

- 删除缓存 Key 时，同步清理对应缓存数据、元数据、定时任务、预警记录，无残留脏资源；同时主动停止该Key正在执行的获取数据任务流，终止无效任务执行

- 支持动态关闭单 Key 定时刷新、预预警能力，支持动态修改 TTL、Cron、提前预警配置

## 五、模块完善优化建议（非原始需求，为生产稳定性补强）

- 增加刷新防抖机制：防止同一 Key 被缓存缺失、预到期、定时多路径并发重复提交任务到引擎

- 拆分读写接口：区分「前端新建缓存接口」和「后端引擎更新缓存接口」，职责隔离

- 增加缓存元数据查询接口，可实时查看 Key 的 TTL、预警时长、Cron 配置、定时状态

- 增加手动强制刷新接口，支持运维/业务主动触发单次缓存刷新

- SSE 连接池自动清理僵尸连接，杜绝内存泄漏，前端支持断线自动重连适配

## 六、模块技术约束

- 技术栈：纯 Hono \+ lru\-cache \+ toad\-scheduler，零 Redis、零 BullMQ 依赖

- 业务计算收口：所有复杂数据刷新逻辑全权交由自研任务引擎，本模块只做调度、缓存、推送、指令下发

- 部署形态：单机内存架构，轻量化、低运维成本
